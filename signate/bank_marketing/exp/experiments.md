# 実験の記録（銀行の顧客ターゲティング）

全実験の数値は `experiments.csv`（1実験1行）にある。ここには各ラウンドの狙い・結果・判断を書く。

## 検証方法

- 層化5分割の交差検証（成約の割合を各分割でそろえる。`random_state=42+seed`）。5回分の検証予測（OOF）をまとめて AUC を計算する。
- train と test は同じ分布（見分けるモデルの AUC 0.501）で、時間の順に分かれてもいない。そのためランダムに分ける検証で本番に近いと判断した。
- LightGBM・CatBoost とも、検証用の分割で早期終了する（LightGBM は 200本、CatBoost は 300本改善しなければ止める）。テストの予測は5つの分割モデルの平均。
- R03 以降は、分け方と seed を3通り変えて平均する（`seeds=(0, 1, 2)`）。

## R01 基準（`r01_baseline.py`）

| ID | 内容 | CV AUC |
|---|---|---|
| lgb_raw | LightGBM、元の16列のみ（カテゴリは LightGBM のカテゴリ扱い） | 0.93519 |
| lgb_fe | ＋簡単な追加特徴量 | **0.93723** |
| cat_fe | CatBoost（depth 6）、lgb_fe と同じ列 | 0.93579 |

追加特徴量: 月の数値（1〜12）、通し日（月×31＋日）、`pdays=-1`（過去の接触なし）フラグ、通話時間の log、通話時間 ÷ 接触回数、残高の符号付き log。

判断:
- 簡単な追加特徴量で +0.002。木のモデルは単調な変換（log）では変わらないので、効いたのは主に通し日と「通話時間 ÷ 接触回数」と考えられる。
- この時点では CatBoost は LightGBM より低い。

## R02 日付ごとの集計（`r02_date_count.py`）

狙い: データに年がないが、元データは 2008〜2010年の記録。日付ごとの件数を見ると、件数の多い日（2008年の大量架電と考えられる）は成約率が低く、件数の少ない日は高い（74件以下の日は 43%）。日付ごとの集計で「時期」を表せるのではないか。

集計は学習＋テストを合わせて行い、目的変数は使わない（テストにもそのまま使える）。

| ID | 内容 | CV AUC | 前との差 |
|---|---|---|---|
| lgb_date1 | ＋日付（月・日）ごとの件数 | 0.93892 | +0.0017 |
| lgb_date2 | ＋日付ごとの携帯電話の比率・連絡手段不明の比率・過去に接触した客の比率・通話時間・接触回数・年齢の平均、月ごとの件数 | 0.93953 | +0.0006 |
| lgb_date3 | ＋日付×連絡手段の件数、日付の中での通話時間・接触回数の順位、同じ属性（年齢・職業・婚姻・学歴・残高）の客の件数 | **0.94051** | +0.0010 |

判断:
- **件数だけで +0.0017**。この課題で一番効いた特徴量。
- 平均・比率・順位も少しずつ効く。「その日の中で通話が長いほうか」（日付の中での通話時間の順位）は、日によって通話の長さの傾向が違うのを補正している。
- 以降は lgb_date3 の特徴量を使う。

## R03 モデルの設定違いと CatBoost（`r03_models.py`、3 seed 平均）

| ID | 内容 | CV AUC |
|---|---|---|
| lgb_l15 | LightGBM、num_leaves=15、min_child_samples=30 | 0.94129 |
| lgb_l63 | LightGBM、num_leaves=63、min_child_samples=50、learning_rate=0.01 | 0.94110 |
| lgb_l31_ff5 | LightGBM、num_leaves=31、feature_fraction=0.5、lambda_l2=5 | **0.94137** |
| cat_d6 | CatBoost、depth=6 | 0.94132 |
| cat_d8 | CatBoost、depth=8、l2_leaf_reg=5 | 0.94125 |

判断:
- 設定による差は小さい（0.9411〜0.9414）。3 seed 平均にしたことで、R02（1 seed、0.9405）より少し上がっている。
- 日付の集計が入ると、CatBoost が LightGBM に追いついた（R01 では 0.0014 低かった）。

## R04 順位平均（`blend.py`）

AUC は順位だけで決まるので、各モデルの予測を順位（0〜1）に直して平均する。

| 組み合わせ | CV AUC |
|---|---|
| LightGBM 3種（l15＋l31_ff5＋l63） | 0.94153 |
| LightGBM（l31_ff5）＋CatBoost（d6） | 0.94193 |
| **LightGBM 2種（l15＋l31_ff5）＋CatBoost 2種（d6＋d8）** | **0.94196** |

判断:
- LightGBM どうしを混ぜても +0.0002 だが、**CatBoost と混ぜると +0.0006**。性質の違うモデルを混ぜるほうが効く。
- 最終は4モデルの順位平均（`final.py` → `submit_blend4.csv`）。テストでの LightGBM と CatBoost の予測の順位相関は 0.984。

## 試していないこと（次の候補）

- 目的変数を使った日付ごとの成約率（分割の中だけで計算する target encoding）。
- 年の推定: 日付ごとの件数・連絡手段・過去の接触の比率から、各日付が 2008/2009/2010 年のどれかを推定する。
- XGBoost・ニューラルネットなど、さらに性質の違うモデルを足す。
- パラメータの自動調整（Optuna）。Jリーグのときのように検証への合わせ込みになりやすいので、やるなら seed を変えた検証で確かめる。
